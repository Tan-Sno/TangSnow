# 自建验证指南 —— 用你自己的环境构建 Rust 核心版

目的：我的构建环境产出的包你不信任（合理，两次翻车）。这份指南让你**在
你自己的 Android Studio 里**把 Rust 核心集成打进棠雪，产物由你亲手构建，
安装结果即为决定性判据——能装：说明集成方案本身没问题，问题在我机器的
so 产物；装不上：说明集成方案有逻辑问题，补丁需要改。两种结果都有价值。

## 前置（约 10 分钟）

- 已能构建棠雪原版的环境（你已有）
- Android NDK（任意 r25+，面板 SDK Manager 勾选即可）
- Rustup：`rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android`

## 步骤

### 1. 编译 Rust 核心（产出三个 .so）

```bash
export ANDROID_NDK_HOME=<你的NDK路径>
cd tangsnow-rs
bash tools/build-android.sh
# 产物：bridge/jniLibs/{arm64-v8a,armeabi-v7a,x86_64}/libtangsnow_core.so
# 脚本已内置 16KB 页对齐链接参数（-Wl,-z,max-page-size=16384），勿删
```

验证 so 对齐（应输出 0x4000）：

```bash
llvm-readelf -l bridge/jniLibs/arm64-v8a/libtangsnow_core.so | grep -m1 LOAD
```

### 2. 应用集成补丁（5 个文件 +60 行）

```bash
cd <棠雪源码根>
git apply rust-core-integration.patch
```

补丁内容（可先 git diff 人工过一遍再应用）：
- `util/UrlUtils.kt`：resolveInfo / extractUrlFromText / isLocalNetworkAddress 三处，Rust 优先、异常回落原实现
- `data/SearchEngines.kt`：searchUrl / displayForUrl 两处，同上
- `data/BookmarkHtml.kt`：parseImportCounted / sanitize / export 三处，同上
- `data/repo/HistoryRepo.kt`：add 一处，同上
- `app/proguard-rules.pro`：CoreNative keep 一条

### 3. 拷入桥接层与 so

```bash
mkdir -p app/src/main/java/io/github/tan_sno/tangsnow/core
cp tangsnow-rs/bridge/CoreNative.kt  app/src/main/java/io/github/tan_sno/tangsnow/core/
cp tangsnow-rs/bridge/CoreBridge.kt  app/src/main/java/io/github/tan_sno/tangsnow/core/ 2>/dev/null || true
cp -r tangsnow-rs/bridge/jniLibs/* app/src/main/jniLibs/
```

（若 bridge/ 下无 CoreBridge.kt，说明它在补丁内已包含，跳过即可。）

### 4. 构建

```bash
./gradlew assembleRelease
```

（你环境有 keystore.properties 则直接出正式签；没有会触发工程签名闸门，
本地验证加 `-Ptangsnow.allowDebugSignedRelease`。）

### 5. 判读

| 结果 | 含义 |
|---|---|
| 能装能开 | 集成方案正确；我的 so 产物有环境特异性问题 → 我重点查 NDK 版本/crt 差异 |
| 装不上 | 方案层有缺陷 → 把 adb install 的具体报错发我，补丁我来改 |

Rust 侧逻辑已经 210/210 单测锁定（2026-10-15 实测；注意默认 `cargo test` **不编译 `jni.rs`**，
JNI 边界要靠交叉编译产物 + 真机验证），你构建的 so 与我构建的 so 只差工具链路径，
行为应完全一致。
