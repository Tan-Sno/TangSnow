# 自建验证指南 —— 用你自己的环境构建 Rust 核心版

目的：我的构建环境产出的包你不信任（合理，两次翻车）。这份指南让你**在
你自己的 Android Studio 里**把 Rust 核心集成打进棠雪，产物由你亲手构建，
安装结果即为决定性判据——能装：说明集成方案本身没问题，问题在我机器的
so 产物；装不上：说明集成方案有逻辑问题，补丁需要改。两种结果都有价值。

## 前置（约 10 分钟）

- 已能构建棠雪原版的环境（你已有）
- Android NDK（任意 r25+，面板 SDK Manager 勾选即可）
- Rustup：`rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android`

## 步骤

### 1. 编译 Rust 核心（产出三个 .so）

```bash
export ANDROID_NDK_HOME=<你的NDK路径>
cd tangsnow-rs
bash tools/build-android.sh
# 产物落点：dist/jniLibs/{arm64-v8a,armeabi-v7a,x86_64}/libtangsnow_core.so
#   （2026-10-15 起该目录**不被 git 跟踪**：唯一进仓、进构建的副本在 app/src/coreRust/jniLibs/）
# 脚本已内置 16KB 页对齐链接参数（-Wl,-z,max-page-size=16384），勿删
# NDK 宿主目录现在按 uname 自动探测；要手工指定：NDK_HOST_BIN=<prebuilt 平台目录>/bin
```

验证 so 对齐（应输出 0x4000）：

```bash
llvm-readelf -l dist/jniLibs/arm64-v8a/libtangsnow_core.so | grep -m1 LOAD
```

### 3. 拷入 .so（桥接代码已在仓库里，**不需要**再拷）

> **2026-10-15 更正**（外部审查 L4）：本节原先让你拷贝一份 `CoreNative.kt` 设计稿
> 到 `app/src/main/java/...`。那份设计稿是接入方案还没定形时的产物
> （101 行，写着"三选一、渐进式"那套），跟真正在用的防护网桥不是同一份东西 ——
> 照原样拷会盖掉 flavor 里的正式实现。设计稿已删。

主线现在用 `core` flavor 承载 Rust 内核，桥与 `.so` 都在仓库里，位置分别是：

- Kotlin 桥：`app/src/coreRust/java/io/github/tan_sno/tangsnow/core/`（`CoreNative.kt`、`CoreBridge.kt`）
- 随包 `.so`：`app/src/coreRust/jniLibs/<abi>/libtangsnow_core.so` ← **构建读的是这里**

自建 `.so` 之后只需覆盖后者：

```bash
for a in arm64-v8a armeabi-v7a x86_64; do
  cp tangsnow-rs/dist/jniLibs/$a/libtangsnow_core.so \
     app/src/coreRust/jniLibs/$a/
done
```

⚠️ §2 那份补丁的处置（为何移出仓库）已写在 §2 的警告里，这里不再抄一遍 ——
逐函数接线请按 PLAN-2026-10-15 的 W1/W2/W3 走，不要靠打补丁。

### 4. 构建

```bash
./gradlew assembleCoreRustRelease
```

（2026-10-15 更新：`core` flavor 维度进来之后要**指名 coreRust** —— 写 `assembleRelease`
会把两个 flavor 都打出来。两个 flavor 共用同一 applicationId 与 versionCode 派生，
一次只能发布其中一个，见 `app/build.gradle.kts` 的 flavor 说明与 `tools/verify_release.py --flavor`。）

（你环境有 keystore.properties 则直接出正式签；没有会触发工程签名闸门，
本地验证加 `-Ptangsnow.allowDebugSignedRelease`。）

### 5. 判读

| 结果 | 含义 |
|---|---|
| 能装能开 | 集成方案正确；我的 so 产物有环境特异性问题 → 我重点查 NDK 版本/crt 差异 |
| 装不上 | 方案层有缺陷 → 把 adb install 的具体报错发我，补丁我来改 |

Rust 侧逻辑已由单测锁定（**计数见 `README.md`「移植范围」一节末尾的「验证结果」，那一处是唯一真源**，
免得两处各写一个数；2026-10-15 实测。注意默认 `cargo test` **不编译 `jni.rs`**，
JNI 边界要靠交叉编译产物 + 真机验证），你构建的 so 与我构建的 so 只差工具链路径，
行为应完全一致。
